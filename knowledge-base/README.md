# 演示规范知识库

本目录保存M4 RAG链路使用的固定演示文档。内容只服务于本仓库的检索、版本过滤和引用测试，不代表真实
遥感行业标准，也不能替代正式业务规范。

逐份文档的作用、使用场景及分工见[知识库规范作用说明](../docs/KNOWLEDGE_GUIDE.md)。该说明供阅读，不参与规范入库。

## 目录约定

```text
knowledge-base/
├── catalog.json              文档身份、路径、检索元数据和版本状态
├── active/                   默认允许召回的当前有效版本
│   ├── dom/
│   ├── quality/
│   ├── coordinate-system/
│   ├── review/
│   └── delivery/
└── historical/               仅用于显式历史版本查询和失效过滤测试
    ├── coordinate-system/
    └── delivery/
```

当前目录只保存标题化Markdown正文，`catalog.json`是唯一元数据来源。M4.3 Loader会先校验目录条目，
再按扩展名显式选择Markdown或纯文本读取器；不得根据文件名猜测版本、适用范围或有效状态。纯文本契约已
支持`.txt`，但当前16份固定演示规范仍全部使用Markdown。

## 元数据约定

计划要求的字段为`document_type`、`satellite_type`、`product_type`、`processing_level`、
`specification_version`、`effective_date`、`expiry_date`和`permission_scope`。目录额外保存稳定文档ID、
标题、相对路径、生命周期以及历史版本的替代文档ID。

`ACTIVE`文档的`expiry_date`和`replaced_by`必须为`null`；`HISTORICAL`文档必须具有失效日期，并指向
同类型的当前有效替代版本。默认检索只能使用`ACTIVE`文档，历史版本必须由调用方明确请求。

M4.12评测标注位于`agent-service/evaluation/rag_cases.jsonl`，每条问题指向本目录中的稳定文档ID和完整章节
路径，并携带统一日期、权限、产品和卫星过滤条件。标注只定义评测期望，不覆盖`catalog.json`元数据，也不
代表已测得真实Embedding或Reranker质量。

## 内容范围与使用边界

14份当前规范覆盖生产输入与完成条件、成果标识和空间信息、目录与清单、云量与几何及辐射检查、
坐标参考与异常返工、复核提交与判定、交付前置条件及材料验收。每节包含核对对象、证据要求、
处理或判定条件，以及不能直接认定通过的反例，供检索后的解释与人工审查使用。
正文面向业务人员；模型行为、Java/Python职责和当前系统实现状态见独立说明，不作为规范条款入库。

这些内容是演示业务的处理要求，不等于全部功能已经实现。当前项目的返工链路止于人工确认后创建待处理任务，
实际修正成果、重新生产及最终验收交付尚未接入。任务、问题和复核状态仍须从Java查询，文档中的
ORDER-003示例不能替代当前事实；规范引用也不能代替实际处理证据。

云量、几何精度和辐射质量文档没有设定通用数值阈值。实际使用时必须取得项目采用的要求与检查材料，
缺少依据时应说明信息不足，不能由模型补造数值、坐标定义或检查结论。

## 2026-10-19语料细化

本次在首次真实全量入库前扩充14份当前演示文档的检查步骤、证据、版本关联和反例。
该次扩充保留文档ID、章节标题、目录元数据和固定业务规则，两份历史文档当时保留原文；这不是正式行业规范的版本发布。
后续正式规范的条款或适用条件变化，应维护独立规范版本、有效期和历史记录，不能仅覆盖旧正文。

离线处理结果仍为16份文档、80个唯一Chunk，50条既有RAG评测标注的目标章节均存在。
该次正文扩充使56个Chunk的内容哈希及ID更新，后续正文整理还会影响ID；保留章节路径不意味着保留原Chunk ID，
也不表示召回质量已经提高。
`README.md`不是catalog条目，不会作为规范正文入库。

容器中的`/knowledge-base`由镜像构建时复制；本机修改文档后，需要重新构建镜像再执行入库，
否则在旧容器中运行命令仍会读取旧正文。当前尚未生成真实知识索引，后续需按新正文完整生成向量再检查`READY`。

## 规范职责整理

后续整理将正文中的Agent行为限制、Java校验方式和未接入能力说明移至独立作用说明，正文改用业务责任、
审批、材料和记录等表述。人工审批与验收责任继续保留为业务制度，模型行为和执行安全不能依赖检索是否命中这些条款。
两份历史文档只清理检索测试说明，历史有效日期、替代关系及业务条款保留。

验收文档的“Agent边界”章节改为“验收责任”；RAG评测`rag-048`改问交付包内部材料，`rag-050`改问验收责任，
并同步后者的目标章节。其他目标章节保持，全部50条标注均能定位。新旧评测题意和语料存在差异，不能直接把报告差值当成模型效果提升。

## 业务表述优化

当前规范增加了开头用途说明，并把较抽象的表述改成具体检查动作：写清哪个任务、哪版成果、哪份材料及下一步由谁确认。
控制资料、像元、接边和文件校验等词补充简短解释；交付条件、返工步骤和验收检查改用列表，状态码保留并配中文说明。
原章节标题、目录元数据和业务条件保持，历史文档继续用于回查原条款。常见词的集中解释见独立作用说明。

再次核对时，补充区分“有证据确认不满足”和“材料不足、暂时不能判断”，避免把材料缺失写成已测得质量超限。
“最近一次复核”明确针对当前成果版本；返工记录、问题关闭和复核通过分别核对。检查情况的文字说明不新增业务状态。

跨文档核对后，进一步分清检查报告形成与质量问题处理闭环：先检查并形成报告，复核据此审查；问题关闭且复核通过后，整套处理和复核环节才算结束。
规范版本、成果版本和参数版本分别说明，复核条件合并重复句；交付材料审查不能放行已明确禁止的内部内容。
