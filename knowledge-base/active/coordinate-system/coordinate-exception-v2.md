# 坐标系异常处理规范

> 演示规范数据，非真实行业标准。

本规范说明怎样发现坐标系问题、安排返工，并在处理后重新复核。

## 异常识别

坐标参考缺失、版本不一致或成果与元数据不一致时，应登记坐标系问题。
异常处理记录应同时说明问题是否关闭、复核是否通过。缺少处理记录或检查材料时，不能认定问题已经解决。
分别查看成果文件中的坐标信息、元数据说明和处理参数，写清哪一项缺失、哪几项不一致。
若只能获取其中部分材料，应说明尚未完成的核查内容，不得补造具体坐标值或实际修复结果。
问题类型应使用COORDINATE_SYSTEM，并关联当前任务和受影响成果，防止把其他任务的问题混入诊断。

## 返工要求

未关闭的坐标系问题需要创建坐标系返工任务。
返工任务应写明原任务号、质量问题编号和需要修改的成果版本。
返工内容应按以下顺序说明：

1. 查清正确的坐标依据，指出原成果或说明材料中哪里有问题。
2. 修改受影响的成果及对应材料，不能只改问题标题或文字说明。
3. 重新检查修改结果，保留新成果版本和检查材料。

返工安排须经有权限的人员确认，并核对最新任务及问题记录。创建返工任务只表示安排已建立，问题仍需后续处理。

## 复核门禁

本节说明复核通过前必须核对的条件。问题处理完成后必须重新提交复核。
复核状态为PENDING（待复核）时，成果不得进入交付流程。
复核人员应检查实际处理记录、新成果版本、坐标一致性检查材料和原问题是否关闭。关键材料缺失时，应列出缺少什么。
四个环节要分别确认：

- 创建返工：已经安排任务。
- 完成返工：已经按要求修改成果，并留下处理记录。
- 关闭问题：办理人员核对检查材料，确认原问题已解决，完成关闭记录。
- 复核通过：复核人员检查材料后，正式确认通过。

以上按办理环节分别说明需要核对的内容，各项结果都应有对应记录。
问题已经关闭但复核尚未通过时，仍不能认定允许交付，还需核对其他交付条件。

## ORDER-003示例

ISSUE-001为OPEN且复核为PENDING，因此建议“创建返工任务并处理后重新提交复核”。
在固定演示场景中，ORDER-003对应任务TASK-003，生产为COMPLETED（已完成）。ISSUE-001类型为COORDINATE_SYSTEM（坐标系问题），状态为OPEN（未关闭），复核为PENDING（待复核），交付为BLOCKED（已阻断）。
因此，订单停在QUALITY_REVIEW（质量复核阶段），原因是坐标系问题未关闭且复核未通过；生产步骤已经完成。
处理说明应分别列出已核实事实、适用规范和后续安排，不应把计划完成后的状态提前写成当前状态。
这些编号和状态仅描述固定示例，实际处理应以该订单的最新正式记录为准。
