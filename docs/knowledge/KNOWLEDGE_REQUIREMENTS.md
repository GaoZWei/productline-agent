规范回答采用RAG，即先从适用资料中检索证据，再依据证据生成回答，并附可回查的版本及原文引用。

## 四、首版行为与接口边界

### 4.1 资料管理流程

```text
上传文件和填写元数据
→ 校验并解析
→ 查看正文和分块预览
→ 人工确认发布
→ 构建候选索引
→ 成功后切换发布版本
```

上传只产生草稿，不能立即影响问答。已发布正文不直接覆盖；新版本发布失败时保留失败记录，旧发布版本继续服务。
重试不能产生重复版本或分块；候选索引与正在服务的发布索引必须隔离，成功切换时不能混用两版证据。

规范版本、生效与失效日期、审核/发布状态、停用状态及索引任务状态分别记录。
停用不等于被新版替代，解析成功也不等于审核或发布成功；历史原文与已有引用保持可回查。
初始16份资料纳管必须保留原有版本身份及14/2关系，不能把两份历史文档发布为当前依据。

原始上传文件保存到独立持久化目录，拒绝路径越界；重启后原件、版本和任务记录保留。
中断任务有明确状态和受控重试入口，不静默当作成功。首版不新增消息队列或复杂任务平台。

### 4.2 问答与页面流程

```text
输入问题及可选业务范围
→ 权限、发布状态、有效期过滤
→ 混合检索与重排
→ 判断证据是否足够
→ 返回答案及版本、章节、原文引用
```

知识库页面提供文档列表与筛选、详情、上传预览、版本历史、发布/停用确认、处理进度和独立规范问答。
独立问答不继承订单会话焦点，复用既有规范问答工作流及Run/Step观测；订单抽屉复用同一发布集合。
默认只检索已发布且当前有效的资料，权限及有效期先于候选排序生效；前端范围参数只能作为提示，不能扩大权限。
